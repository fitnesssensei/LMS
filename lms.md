# LMS — сборка и запуск Docker-образа из терминала

Инструкция для macOS (Apple Silicon), проект в `~/Desktop/LMS`.

Состав проекта:

- `app.py` — минимальный HTTP-сервер на стандартной библиотеке Python, слушает порт из `$PORT` (по умолчанию `8000`), в приветствии подставляет значение `$APP` (по умолчанию `LMS`);
- `Dockerfile` — базовый образ `python:3.11-slim`, создание системного пользователя `appuser`, запуск от непривилегированного пользователя.

---

## 0. Диагностика: почему `docker build` падает

Две ошибки, которые встречаются чаще всего, и у них разные причины.

### `Cannot connect to the Docker daemon at unix:///Users/<user>/.docker/run/docker.sock`

Установлен только **Docker CLI**. Сам демон на macOS живёт внутри легковесной Linux-VM, которую поднимает приложение Docker Desktop. Если приложение не запущено — клиент подключаться некуда.

Важный нюанс: `docker context ls` при этом показывает `desktop-linux` как активный контекст, а файл `~/.docker/run/docker.sock` существует, но остаётся от прошлого запуска. То есть Docker «выглядит запущенным», хотя процесса нет. Проверить, есть ли живой процесс:

```bash
pgrep -fl "Docker Desktop"
```

Пустой вывод — демон не запущен.

### `docker: 'docker buildx build' requires 1 argument`

Это **не** про демон. В современном Docker CLI команда `docker build` — алиас к `docker buildx build`, который требует минимум один аргумент: путь к контексту сборки. Чаще всего просто забыта точка в конце команды.

```bash
docker build -t myapp:test    # ❌ нет контекста сборки
docker build -t myapp:test .  # ✅ точка = текущая папка
```

Порядок важен: эта ошибка выводится раньше, чем CLI попытается подключиться к демону, поэтому она может маскировать первую проблему.

## 1. Запустить демон Docker

Отдельной команды `dockerd` на macOS нет — запускается именно приложение:

```bash
open -a Docker
```

Если приложение не найдено, запустить по полному пути:

```bash
open /Applications/Docker.app
```

При первом запуске Docker Desktop может показать окно с лицензией или онбордингом — их нужно принять один раз мышкой. В строке меню появится значок кита.

## 2. Дождаться готовности демона

`open` возвращает управление мгновенно, а VM с демоном стартует ещё 20–60 секунд. Надёжнее проверять циклом, чем ждать «на глазок»:

```bash
for i in $(seq 1 60); do
  if docker info >/dev/null 2>&1; then echo "✅ Docker готов"; break; fi
  echo "⏳ ожидание демона... ($i)"
  sleep 2
done
```

Максимум 2 минуты ожидания. Проверка вручную — та же команда, что падала раньше:

```bash
docker info
```

Признак успеха — в выводе есть секция `Server:`. Быстрый способ посмотреть только это:

```bash
docker version
```

Должны присутствовать **обе** секции: `Client:` и `Server:`. Если `Server:` нет — демон ещё не поднялся.

## 3. Собрать образ

```bash
cd ~/Desktop/LMS
docker build -t myapp:test .
```

Точка в конце обязательна — это контекст сборки, то есть текущая папка. Команда должна выполняться из директории, где лежит `Dockerfile`.

Что происходит внутри:

1. скачивается базовый образ `python:3.11-slim` (~50 МБ; на Apple Silicon берётся arm64-вариант);
2. создаётся системный пользователь `appuser` (uid/gid 1000);
3. копируется `app.py` с `--chown=appuser:appuser`;
4. контейнер переключается на `USER appuser`.

Внешних зависимостей у приложения нет — только стандартная библиотека, поэтому `pip install` не нужен.

## 4. Проверить, что образ появился

```bash
docker images myapp:test
```

Ожидается строка с репозиторием `myapp` и тегом `test`.

## 5. Запустить контейнер

На переднем плане — удобно видеть логи, остановка по `Ctrl+C`:

```bash
docker run --rm -p 8000:8000 -e APP=LMS myapp:test
```

В фоне:

```bash
docker run -d --name lms-test -p 8000:8000 -e APP=LMS myapp:test
```

Разбор флагов:

| Флаг | Что делает |
| --- | --- |
| `--rm` | удалить контейнер после остановки |
| `-d` | запустить в фоне (detached) |
| `--name lms-test` | задать имя контейнера вместо случайного |
| `-p 8000:8000` | пробросить порт `хост:контейнер` |
| `-e APP=LMS` | переменная окружения, подставляется в приветствие |

## 6. Проверить, что приложение отвечает

Во втором терминале, либо после запуска с `-d`:

```bash
curl http://localhost:8000/
```

Ожидаемый ответ:

```
Hello from LMS! 👋
Path: /
```

Чтобы поменять порт на хосте, например на 9000, меняется только левая часть проброса: `-p 9000:8000`.

## 7. Остановить

Контейнер в фоне:

```bash
docker stop lms-test
```

Контейнер на переднем плане — `Ctrl+C`. Убедиться, что ничего не осталось:

```bash
docker ps
```

## Если что-то не сработало

### `open -a Docker` не находит приложение

Проверить, что оно вообще установлено, и нет ли альтернативы (Rancher Desktop, OrbStack):

```bash
ls -d /Applications/*.app | grep -i -E 'docker|rancher|orbstack'
```

У альтернативных рантаймов свой способ запуска, хотя Docker CLI остаётся тем же.

### Демон не поднялся за 2 минуты

Проверить активный контекст — звёздочка должна стоять на `desktop-linux`:

```bash
docker context ls
```

Если активен `default` (он смотрит в `unix:///var/run/docker.sock`, которого на macOS нет), переключиться:

```bash
docker context use desktop-linux
```

### Демон завис, нужно перезапустить

```bash
osascript -e 'quit app "Docker"'
sleep 5
open -a Docker
```

Если не помогает — в Docker Desktop: иконка кита → Troubleshoot → Restart. Логи: `~/Library/Containers/com.docker.docker/Data/log/`.

### Не хочется держать Docker Desktop

Альтернатива — лёгкий демон без GUI, colima (потребуется Homebrew):

```bash
brew install colima docker
colima start
```

После этого шаги 3–7 выполняются без изменений, Docker CLI остаётся тем же.
